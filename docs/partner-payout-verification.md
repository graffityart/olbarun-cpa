# 마이픽업 출금 본인확인·부정거래 방지 구현 기준

## 출금 신청 전 검수

파트너 본인 명의 계좌 확인, 통장 사본, 개인 신분확인 또는 사업자 등록 증빙을 별도 제출받는다. 주민등록번호 뒷자리, 주소 등 불필요한 정보는 가리고 제출하도록 안내한다. 만 15세 이상 이용 정책은 실제 생년월일 확인·법정대리인 동의 등 관련 법률 검토 후 서버에서 강제한다. 단순 문구 표시만으로 연령 검증을 완료했다고 보지 않는다.

## 파일 보안

- 업로드는 로그인된 본인만 허용하며 서버가 파트너 ID를 결정한다.
- 비공개 Blob 저장소를 사용하고 공개 URL을 발급하지 않는다. PDF/JPEG/PNG 등 허용 형식의 파일 시그니처와 크기를 검사한다. **악성코드 검사는 아직 구현되지 않았다.** 업로드 횟수 제한은 0021 마이그레이션과 `PAYOUT_UPLOAD_RATE_LIMIT=enabled`를 적용할 때만 활성화된다. 운영 활성화 전에 두 항목을 검증한다.
- 신분증과 통장 사본은 **관리자 전용 검수 API**를 통해서만 단기 접근하며 접근 시각·검수자·대상·행위를 감사로그에 남긴다. 원본 문서 URL을 HTML, 클라이언트 로그, 알림에 노출하지 않는다.
- DB에는 파일 원본 대신 비공개 저장 경로와 상태만 저장한다. 주민등록번호·계좌번호 원문을 감사로그에 남기지 않는다.
- 검수 상태: NOT_SUBMITTED → PENDING → APPROVED / REJECTED. 반려 시 수정 제출을 허용하며, 승인 후 계좌 변경 시 재검수를 요구한다.
- 검수 자료 보관 기간·삭제 및 열람 정책을 개인정보 처리방침에 명시한다. 법적 의무 및 실제 보관 필요성을 확인하고 만료 후 안전하게 삭제한다.

## 지급 차단과 세금

- 운영 적용 전에 파트너 출금 POST 및 관리자 지급 승인·지급완료 API 모두에서 승인된 KYC 상태와 은행계좌 명의 일치 여부를 **서버 측에서** 검사한다. 기존 요청의 지급을 막지 않도록 마이그레이션·관리자 운영 준비를 완료한 후 기능 플래그로 단계적으로 적용한다.
- 정산의 deductionAmount / paymentAmount는 현재 신청 시 0원 차감·전액 지급으로 생성된다. 운영 요청 기준은 개인 파트너 원천징수 3.3%, 일반과세 사업자 공급가액 + 부가세 10%, 세금계산서 선발행(수신 이메일 c0810@naver.com)이다. 면세·간이과세자 및 소득 유형별 법적 적용 여부를 세무 전문가와 확인하고 공제·장부·지급명세서 처리를 일치시킨다. 현재 안내 문구만 변경했으며 실제 금액 계산 로직은 미구현이다.
- 목요일 마감·금요일 지급은 운영 정책으로 확정한 후 한국시간(Asia/Seoul), 공휴일 예외 및 처리 지연 안내를 구현한다.
- 신분증 제출은 일반적인 자금세탁방지 의무가 모든 플랫폼에 동일하게 적용된다는 의미가 아니며, 개인정보 최소 수집 및 관련 법적 근거를 검토해야 한다.

## 이번 변경 범위

출금 안내 UI, KYC 메타데이터 마이그레이션, 비공개 파일 업로드, 관리자 열람·승인/반려, 계좌 변경 재검수 해제 API를 개발 브랜치에 구현했다. 출금 신청과 관리자 승인·지급 단계에서 검수 상태와 계좌 HMAC 지문을 검사하는 로직은 **PAYOUT_KYC_ENFORCEMENT=enabled**일 때만 작동한다. 운영 DB 마이그레이션 및 운영 배포는 아직 수행하지 않았다. 악성코드 검사, 문서 보존·삭제 정책과 실제 API 통합 검증은 남아 있다. 업로드 요청 횟수 제한은 개발 브랜치에 구현했지만 기본 비활성이다.

## 단계적 출금 차단 활성화

파트너 출금 POST에는 `PAYOUT_KYC_ENFORCEMENT=enabled`인 경우에만 트랜잭션 내 본인확인 승인 상태 검사 및 `PAYOUT_VERIFICATION_REQUIRED`(HTTP 409) 반환을 추가했다. 기본값은 비활성이다. 운영 적용 전 0020 마이그레이션, 비공개 파일 저장/열람 테스트, 관리자 승인 감사로그, 계좌 명의 대조, 지급 승인·완료 API 차단 및 개인정보 보관 정책을 먼저 완료해야 한다. 환경변수를 켜기 전에 기존 파트너의 검수 전환 절차를 마련한다.

## 계좌 변경 시 재검수 필수

현재 출금 신청 시 은행명·계좌번호·예금주를 자유 입력한다. 승인된 신분증과 통장 사본이 특정 계좌에 연결되어 있지 않으면 다른 계좌로 지급할 수 있으므로 **운영 KYC 강제 플래그는 전체 보안·개인정보 검증이 끝나기 전까지 활성화하면 안 된다**. 현재 관리자가 승인된 계좌의 재검수를 허용하면 기존 상태를 REJECTED로 전환하고 HMAC 지문을 제거하며, 파트너가 서류를 재제출할 수 있다. REQUESTED/APPROVED 상태의 정산이 있으면 재검수 해제를 거부한다. 계좌 변경 전용 셀프서비스는 아직 없다. 검수 승인 시 정규화된 은행명·계좌번호·예금주에 대한 서버 측 HMAC 지문을 기록하고, 출금 신청 및 관리자 지급 직전 동일 지문인지 검사한다. 비밀키는 별도 환경변수로 관리하며 로그·클라이언트에 노출하지 않는다. 기존 승인 데이터의 지문이 없으면 재검수 처리한다.

## 운영 활성화 전 필수 점검

1. `0020_partner_payout_verifications.sql`과 `0021_partner_payout_upload_limits.sql`을 검증된 절차로 적용하고 롤백·백업 계획을 마련한다. `PAYOUT_UPLOAD_RATE_LIMIT=enabled`는 0021 적용 후에만 설정한다.
2. `PAYOUT_ACCOUNT_FINGERPRINT_SECRET`을 최소 32바이트 이상의 안정적인 비밀값으로 설정한다. 값이 변경되면 기존 지문과 일치하지 않으므로 회전 절차 없이 교체하지 않는다. 비밀값을 로그·클라이언트에 노출하지 않는다.
3. 비공개 Blob 읽기·쓰기 권한, 파일 악성코드 검사, 요청 빈도 제한, 불필요한 개인정보 마스킹 및 보존·삭제 정책을 검증한다.
4. 기존 파트너를 재검수할 운영 절차와 담당자를 정하고, 출금 보류 상황을 안내한다.
5. 테스트 환경에서 파일 업로드→관리자 열람→승인→출금→계좌 변경 재검수→재승인까지 실제 API 통합 테스트를 완료한다.
6. `PAYOUT_KYC_ENFORCEMENT=enabled`는 위 검증 후 별도 승인하에 적용한다. 현재 개발 브랜치만 변경했으며 운영 적용은 하지 않았다.

## 업로드 요청 제한 및 개인정보 최소화

- `PAYOUT_UPLOAD_RATE_LIMIT=enabled`일 때 로그인한 파트너별 1시간에 5번까지 업로드 API 요청을 허용한다. 6번째부터 HTTP 429 및 `Retry-After`를 반환한다. 성공한 업로드뿐 아니라 잘못된 형식 등 실패한 시도도 횟수에 포함된다. DB의 원자적 upsert를 사용해 여러 서버 인스턴스 사이에서 제한을 공유한다.
- 제한 테이블은 파트너 ID, 시간창 시작, 시도 횟수만 보유한다. 신분증 이미지, 주민등록번호, IP 주소를 기록하지 않는다. 단, 시간창이 지난 행도 자동 삭제되지는 않으므로 별도 보존·정리 절차를 마련해야 한다.
- 서류 파일은 실제 PDF/JPEG/PNG 시그니처와 파일 확장자를 함께 확인한다. 이는 악성코드 검사, PDF 활성 콘텐츠 제거, 이미지 메타데이터 제거 또는 주민등록번호 자동 마스킹을 의미하지 않는다.
- 현재 `privacyMaskConfirmed`는 이용자 확인 체크만 검사한다. 서버가 실제로 뒷자리 7자리를 가렸는지 판별하지 못하므로 운영 전 관리자 육안 검수 및 민감정보 노출 시 즉시 반려·삭제 절차가 필요하다.
- 보존 기간을 임의로 확정하지 않는다. 법률·회계 보존 의무와 최소 수집 원칙을 검토한 후 만료 문서에 대한 비공개 Blob 삭제, DB 경로 정리, 감사 기록을 별도 구현한다.

## 운영 배포 체크리스트 (기본 비활성)

- [ ] Vercel Production에서 `PAYOUT_KYC_DOCUMENT_UPLOAD`은 미설정 또는 disabled 상태로 유지한다. UI·업로드 API·관리자 검수 목록은 이 플래그가 enabled일 때만 신규 KYC 테이블을 조회한다.
- [ ] `PAYOUT_KYC_ENFORCEMENT`와 `PAYOUT_UPLOAD_RATE_LIMIT`은 운영 DB 마이그레이션·테스트 전까지 비활성으로 유지한다. 업로드를 켜기 전에 0020과 0021 모두 적용하고 검증한다.
- [ ] 비공개 Blob 토큰, 계좌 지문용 비밀키, 관리자 권한, 개인정보 처리방침 및 최소 보존 기간을 검증한다.
- [ ] 민감정보가 포함된 PDF/이미지의 악성코드 검사·불필요한 정보 가림 확인·삭제 절차를 완료한다.
- [ ] 테스트 파트너로 업로드→검수→반려/재제출→승인→출금/지급→계좌 변경 재검수 시나리오를 실행한다. 테스트 서류에 실제 주민등록번호를 사용하지 않는다.
- [ ] GitHub 필수 체크와 Vercel Production 빌드가 성공했는지 확인하고, 실제 운영 도메인의 공개 페이지 및 관리자/파트너 로그인 흐름을 점검한다.

**주의:** 코드가 운영에 배포되어도 위 플래그가 비활성이면 KYC 서류 접수는 시작되지 않는다. 이 상태를 기능 오작동으로 판단해 임의로 플래그를 활성화하지 않는다. 마이그레이션 SQL을 자동 실행하거나 기존 파트너의 출금을 일괄 차단하지 않는다.
