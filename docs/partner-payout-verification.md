# 마이픽업 출금 본인확인·부정거래 방지 구현 기준

## 출금 신청 전 검수

파트너 본인 명의 계좌 확인, 통장 사본, 개인 신분확인 또는 사업자 등록 증빙을 별도 제출받는다. 주민등록번호 뒷자리, 주소 등 불필요한 정보는 가리고 제출하도록 안내한다. 만 15세 이상 이용 정책은 실제 생년월일 확인·법정대리인 동의 등 관련 법률 검토 후 서버에서 강제한다. 단순 문구 표시만으로 연령 검증을 완료했다고 보지 않는다.

## 파일 보안

- 업로드는 로그인된 본인만 허용하며 서버가 파트너 ID를 결정한다.
- 비공개 Blob 저장소를 사용하고 공개 URL을 발급하지 않는다. PDF/JPEG/PNG 등 허용 형식의 실제 파일 시그니처, 크기, 악성코드 검사, 업로드 횟수 제한을 검증한다.
- 신분증과 통장 사본은 **관리자 전용 검수 API**를 통해서만 단기 접근하며 접근 시각·검수자·대상·행위를 감사로그에 남긴다. 원본 문서 URL을 HTML, 클라이언트 로그, 알림에 노출하지 않는다.
- DB에는 파일 원본 대신 비공개 저장 경로와 상태만 저장한다. 주민등록번호·계좌번호 원문을 감사로그에 남기지 않는다.
- 검수 상태: NOT_SUBMITTED → PENDING → APPROVED / REJECTED. 반려 시 수정 제출을 허용하며, 승인 후 계좌 변경 시 재검수를 요구한다.
- 검수 자료 보관 기간·삭제 및 열람 정책을 개인정보 처리방침에 명시한다. 법적 의무 및 실제 보관 필요성을 확인하고 만료 후 안전하게 삭제한다.

## 지급 차단과 세금

- 운영 적용 전에 파트너 출금 POST 및 관리자 지급 승인·지급완료 API 모두에서 승인된 KYC 상태와 은행계좌 명의 일치 여부를 **서버 측에서** 검사한다. 기존 요청의 지급을 막지 않도록 마이그레이션·관리자 운영 준비를 완료한 후 기능 플래그로 단계적으로 적용한다.
- 정산의 deductionAmount / paymentAmount는 현재 신청 시 0원 차감·전액 지급으로 생성된다. 운영 요청 기준은 개인 파트너 원천징수 3.3%, 일반과세 사업자 공급가액 + 부가세 10%, 세금계산서 선발행(수신 이메일 c0810@naver.com)이다. 면세·간이과세자 및 소득 유형별 법적 적용 여부를 세무 전문가와 확인하고 공제·장부·지급명세서 처리를 일치시킨다. 현재 안내 문구만 변경했으며 실제 금액 계산 로직은 미구현이다.
- 목요일 마감·금요일 지급은 운영 정책으로 확정한 후 한국시간(Asia/Seoul), 공휴일 예외 및 처리 지연 안내를 구현한다.
- 신분증 제출은 일반적인 자금세탁방지 의무가 모든 플랫폼에 동일하게 적용된다는 의미가 아니며, 개인정보 최소 수집 및 관련 법적 근거를 검토해야 한다.

## 이번 변경 범위

출금 안내 UI와 KYC 메타데이터 마이그레이션을 추가했다. **실제 파일 업로드·관리자 열람·승인 API 및 출금 강제 차단은 아직 구현되지 않았다.** 운영 DB에 마이그레이션을 적용하거나 운영 사이트에 배포하기 전에 보안 기능과 테스트를 완성해야 한다.
