# 마이픽업 외부 CPA Postback 연동

## 서버 간 전환 보고

파트너의 추적 링크 `https://www.mypickup.kr/c/{code}`를 클릭하면 마이픽업에서 클릭 기록을 생성하고 광고주 랜딩 URL에 `click=CLK-...` 쿼리를 붙여 이동합니다. 광고주는 클릭 ID를 신청 세션에 보존하고, **고객의 개인정보 처리 및 제3자 제공 동의를 받은 경우에만** 서버에서 전환을 보고합니다.

**POST** `https://www.mypickup.kr/api/postback/cpa`

요청 헤더:
- `Content-Type: application/json`
- `x-cpa-postback-secret: <해당 캠페인 전용 인증키>`

요청 JSON 예시 (실제 개인정보가 아닌 테스트용 값):

```json
{
  "campaignId": "<관리자 캠페인 UUID>",
  "click": "CLK-0123456789ABCD",
  "name": "테스트고객",
  "phone": "01000000000",
  "region": "부산",
  "privacy": true,
  "thirdParty": true
}
```

성공 시 `201` 및 `conversionCode` 반환. 이미 사용된 클릭 ID 또는 중복 전화번호 등은 `409`, 인증 실패는 `401`, 미설정은 `503`입니다.

## 운영 전 체크리스트

1. Vercel Production에 `CPA_POSTBACK_SECRET` 설정 후 새 배포를 완료합니다.
2. 관리자가 로그인한 상태에서 `GET /api/admin/campaigns/{campaignId}/postback-key`로 **해당 캠페인 전용 인증키**를 조회합니다. 응답의 `token`을 광고주 서버에 **서버 전용 비밀값**으로 저장합니다. HTML, 브라우저 JS, 앱 번들, 공개 문서, 로그에 노출하지 않습니다.
3. 광고주 서버는 클릭 ID와 캠페인 UUID를 신청 세션에 보관하고, 신청 성공 시 한 번만 전송합니다.
4. 실제 발급 링크 클릭 → 외부 랜딩 → 신청 → 관리자 전환 DB → 파트너 귀속까지 테스트합니다.
5. 같은 클릭 ID의 반복 요청과 동시에 들어온 요청, 잘못된 인증키, 다른 캠페인 ID, 미동의 요청을 검증합니다.
6. 인증키는 캠페인 ID별로 마스터키에서 HMAC 파생됩니다. **마스터키 자체를 광고주에게 전달하지 마세요.** 관리자만 캠페인별 키를 조회할 수 있습니다. 마스터키를 변경하면 모든 캠페인 키가 동시에 바뀌므로 키 교체 시 광고주 서버도 갱신해야 합니다.
7. 현재 `promoBanners`는 캠페인 JSON 설정에 포함됩니다. 이미지가 많아지면 Blob 등 별도 저장소로 이전하세요.

## 참고

- 외부 랜딩에서는 마이픽업 도메인의 쿠키를 읽을 수 없습니다. URL의 `click` 값을 광고주 서버에 저장해야 합니다.
- 접수 성공(`RECEIVED`)은 최종 승인이나 지급 완료를 뜻하지 않습니다.
- 본 API는 인증된 서버 간 요청 전용이며, 브라우저에서 직접 호출하면 안 됩니다.
