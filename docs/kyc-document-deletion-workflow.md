# KYC 서류 삭제 작업 설계 (실행 비활성)

이 문서는 **설계 계약**이며 실행 코드, 운영 마이그레이션, 관리자 승인 API를 활성화하지 않는다. 보관 기간은 법률·회계·분쟁 보존 의무 검토 및 개인정보 처리방침 승인 전까지 미정이다.

## 상태 및 승인

- `DRAFT`: 관리자 후보 조회 결과에 대한 작업 초안. 개별 파트너·Blob 경로는 일반 응답에 노출하지 않는다.
- `REVIEW_REQUIRED`: 보관 기간, 법적 보존(legal hold), 지급 진행 상태, 문서 참조를 점검해야 한다.
- `APPROVED`: 승인 권한을 가진 별도 관리자에 의해 승인된 상태. 요청자와 승인자를 분리하고, 승인 시점·정책 버전·사유·후보 수·해시를 감사 기록에 남긴다.
- `RUNNING`: 단일 작업자가 작업 잠금을 획득한 상태. 삭제 직전 DB 잠금과 최신 상태 재검증이 필수다.
- `PARTIAL_FAILURE`: 일부 Blob 삭제 실패. 실패 원인 유형과 재시도 횟수만 기록하고 파일 내용·경로는 일반 로그에 남기지 않는다.
- `COMPLETED`: Blob 삭제 성공 및 DB 경로 정리 확인. 문서별 완료 증거를 감사 기록에 남긴다.
- `CANCELLED`: 실행 전 승인 철회 또는 조건 불충족으로 중단.

## 멱등성 및 재시도 계약

1. 작업 ID와 대상 서류 버전(제출 시점·검증 ID·참조 경로의 내부 해시)을 결합한 고유 키를 사용한다. 동일 작업 중복 실행은 DB 유니크 제약과 잠금으로 차단한다.
2. 저장소 삭제 전 해당 파트너 검증 행을 잠그고, 현재 Blob 경로·상태·지급 진행 여부·법적 보존 여부를 다시 확인한다. 조건이 달라졌다면 해당 항목을 건너뛰고 재승인을 요구한다.
3. Blob 삭제 성공과 DB 갱신은 단일 원자적 트랜잭션이 될 수 없다. 따라서 문서별 상태를 `PENDING → BLOB_DELETE_CONFIRMED → DB_REFERENCE_CLEARED`로 나누고 각 단계의 재시작을 허용한다.
4. 삭제 요청 타임아웃 등 결과가 불명확하면 Blob 존재 여부를 재확인한다. 저장소의 '이미 없음' 결과는 같은 문서 버전의 삭제 성공으로 처리할 수 있으나, 다른 제출 버전의 파일은 건드리지 않는다.
5. DB 참조 정리는 현재 행이 승인 당시 문서 버전과 일치할 때만 수행한다. 삭제와 동시에 재제출된 새로운 경로를 지우지 않도록 조건부 갱신을 사용한다.
6. 실패 항목은 지수 백오프·최대 재시도 횟수·관리자 수동 검토 경로를 둔다. 재시도 과정에서 개인정보를 로그나 응답에 노출하지 않는다.
7. 백업과 저장소 복제본의 보존 기간 및 삭제 처리 방식은 별도 확인한다. 감사 로그에는 문서 원문이나 전체 주민등록번호를 기록하지 않는다.

## 배포 및 테스트 게이트

- 보관 기간·법적 보존 판단·관리자 역할 분리·감사 정책을 승인하기 전에는 `APPROVED` 상태 전이 및 실행 워커를 구현·활성화하지 않는다.
- 합성 문서로 중복 요청, 동시 재제출, 지급 요청과 삭제 경합, Blob 삭제 성공 후 DB 실패, Blob 타임아웃, 재시도 한도 초과, 권한 거부, 취소를 검증한다.
- 격리된 Neon DB 및 비공개 Blob 스토어가 준비되기 전에는 실제 HTTP 통합 테스트를 수행하지 않는다.
- 운영 데이터 삭제, DB 마이그레이션, 환경변수 변경은 이 문서 작성 범위에 포함되지 않는다.
